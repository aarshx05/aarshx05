Why 32 Findings Were Removed

Dev Environment Configs 7

  • SP-003 SP-004 SP-005 — Passwords equal usernames / default passwords. All in evoting-e2e-dev, the development sandbox. Production uses a secret manager.
  • SP-016 — JDWP debug ports. Expected in dev. Not in prod manifests.
  • SP-019 — No K8s securityContext. Dev environment. Prod enforces PodSecurity.
  • SP-020 — RSA key committed. File is localhost.key — a self-signed dev cert.
  • SP-061 — Internal hostname in ingress. Dev env, .pnet.ch already publicly known as Swiss Post.

Misunderstood Architecture 12

  • SP-011 — "Missing cert verification." Netty without explicit trustManager uses JVM default cacerts. Verification is active.
  • SP-014 — "HTTP not HTTPS." These are localhost URLs in the SDM desktop app. Traffic never leaves the machine.
  • SP-015 — H2C enabled. Standard behind TLS-terminating ingress. Internal hop is cleartext by design in K8s.
  • SP-021 — "No authorization beyond mTLS." mTLS IS application-level authorization — mutual certificate authentication.
  • SP-023 — 15-min replay window. Standard TOTP behavior (RFC 6238: T-1, T, T+1). Challenges tracked against replay.
  • SP-038 — No CSRF tokens. The voting API uses protocol-level auth (SVK + challenge), not cookie sessions. CSRF not applicable.
  • SP-045 — SendVote idempotence key missing attempt counter. Re-voting is not allowed in Swiss e-voting. Correct by design.
  • SP-046 — CONFIRM from CONFIRMED state. Idempotent: returns cached result without re-validating BCK.
  • SP-050 — Ciphertext in toString(). ElGamal ciphertexts are public by construction — published on the bulletin board for verification.
  • SP-051 — modInvert skips coprimality check. Documented precondition, callers guarantee it. Standard optimization.
  • SP-062 — Non-constant-time equals on ZKP values. Finding itself states "no practical impact" — both values are public in Fiat-Shamir.
  • SP-029 — JS secrets in memory. Fundamental browser platform limitation. Uint8Array is marginally better but GC still controls lifetime.

Operational Context 5

  • SP-034 — Direct Trust Tool hardcoded session ID. Tool runs on air-gapped machines during key ceremonies. Not network-accessible.
  • SP-036 — Direct Trust Tool Electron plugins. Same air-gapped ceremony environment. No browser plugin exploit path.
  • SP-044 — Dispute resolver maintains vote-voter linkages. This is the tool's designed purpose — resolving per-voter disputes requires per-voter data.
  • SP-048 — OvApi on window. The full API is already accessible via DevTools Network tab. No additional attack surface.
  • SP-012 — SDM unlimited upload. SDM is a local Electron app. Spring Boot backend is localhost. No external attack surface.

Mitigating Controls 8

  • SP-027 — BCK "limited entropy." 5 attempts on 106 = 0.0005% success rate. Not exploitable at individual level.
  • SP-031 — SDM shell spawn with shell:true. Arguments are application-controlled, not user-supplied. No injection vector.
  • SP-041 — "Log injection." SLF4J {} parameterized logging prevents injection. Not vulnerable to Log4Shell pattern.
  • SP-052 — Argon2 LESS_MEMORY. Both profiles comply with RFC 9106. 64 MiB sufficient given 5-attempt lockout.
  • SP-053 — JSON.stringify comparison. Property order is deterministic in V8/SpiderMonkey for same-construction objects.
  • SP-055 — Vote cache fingerprint. Client-side only. Network observer sees encrypted vote regardless.
  • SP-060 — Idempotency keys contain voter info. Required for functional idempotency. Hashing doesn't change associated data.
  • SP-063 — Skipping statement verification. The info finding is about code consistency, but the precondition is documented and tested.
