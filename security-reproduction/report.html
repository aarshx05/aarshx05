D-06 Cross-Domain PII Cookie Shared Across All *.deriv.com Subdomains Confirmed Medium
Source Code Evidence

client-store.js:1207-1234 — setCookieAccount():

const domain = /deriv\.(com|me|be)/
    .test(window.location.hostname)
    ? deriv_urls.DERIV_HOST_NAME  // "deriv.com"
    : window.location.hostname;

Cookies.set('client_information', {
    loginid, email, landing_company_shortcode,
    currency, residence, first_name, last_name,
    name, preferred_language, user_id
}, { domain });
What Gets Shared

The client_information cookie contains PII (email, full name, loginid, user_id, currency, country of residence) and is set on domain deriv.com with no HttpOnly flag. This makes it readable by JavaScript on any *.deriv.com subdomain.

Impact: XSS on any Deriv subdomain (including SmartTrader, which has no CSP and wide-open CORS) exfiltrates PII for every authenticated user: email, name, account ID, and country.

Not Reproducible

D-01 Bot evaluateExpression() Code Execution Not Reproducible
Original Claim

new Function('return ' + value.trim())() in index.js:719 executes arbitrary code from malicious .xml bot strategy files.

Why It Fails

All values pass through Blockly.JavaScript.javascriptGenerator.valueToCode() before reaching evaluateExpression(). This sanitization layer:

  • Text blocks: Single-quoted with internal quotes backslash-escaped
  • Math blocks: Enforce numeric values (non-numeric → 0)
  • Variable blocks: Special characters replaced with underscores
Tested on Live bot.deriv.com

10 distinct injection vectors tested — malicious XML files loaded into live Blockly workspace. All payloads were sanitized by valueToCode() before reaching new Function(). Zero code execution achieved.

D-27 OAuth CSRF — Missing State Parameter Not Reproducible

Deriv migrated to Ory-based OIDC. The live Google OAuth flow now includes state (long random value), code_challenge (PKCE S256), and response_type=code. The old oauth.deriv.com endpoint 301-redirects to deriv.com.

D-09 Auth Tokens Persist in URL Fragment Not Reproducible

The old token-in-URL callback (?acct1=&token1=) is no longer consumed. The new Next.js app uses OIDC authorization codes through Ory. Tokens passed in URL params are not processed by the current production site.

D-19 Open Redirect via ext_platform_url Not Reproducible

The ext_platform_url handler existed in the deriv-app React SPA. That SPA is no longer deployed — app.deriv.com redirects to deriv.com (Next.js). Tested with Playwright: no redirect occurs.

D-10 Payment Agent Stored XSS Not Reproducible

All payment agent data (name, further_information, URLs, phone, commission) is rendered through React JSX text interpolation {value}, which auto-escapes HTML entities. Zero uses of dangerouslySetInnerHTML, .html(), or innerHTML in the payment agent components. False positive.

Methodology

Each finding was tested against live production targets using Playwright (Chromium) with network interception, curl for header verification, and direct code path tracing in the open-source repositories. Testing was performed under Deriv's HackerOne bug bounty program scope.
